# 原生契约 · 大肥鱼桌宠悬浮窗

这份文档写清楚**这个仓库里没有、但打包成 APK 必须有**的东西。

原因：本仓库（以及用户的 `somnacare` 源）都**没有 `android/` 工程目录**——
`npx cap add android` 生成的那部分不在版本控制里。所以下面这些配置项
无法在这个仓库里验证，只能由构建环境提供。

**诚实声明：本次移植的 Java 代码没有经过编译器。** 我能在本地做到的只有静态核对
（跨文件符号、括号平衡、精灵图契约、枚举顺序），已全部写进 `tools/verify-pet.mts`。
真正的编译验证必须在你的 APK 构建环境里做。

---

## 一、宿主 `AndroidManifest.xml` 需要的条目

`plugins/cap-gemma-llm/android/src/main/AndroidManifest.xml` 是**空的**
（`<manifest …></manifest>`），所有 service 声明都在宿主 App 的清单里。
加桌宠需要以下几项——护眼滤镜那几项如果之前已经能跑，就只补桌宠这一段。

```xml
<!-- 悬浮窗权限（与护眼滤镜共用同一项系统授权） -->
<uses-permission android:name="android.permission.SYSTEM_ALERT_WINDOW" />
<!-- 前台服务：桌宠常驻需要，Android 14+ 必须声明具体类型 -->
<uses-permission android:name="android.permission.FOREGROUND_SERVICE" />
<uses-permission android:name="android.permission.FOREGROUND_SERVICE_SPECIAL_USE" />
<!-- 开机自启（若沿用现有床前提醒的自启逻辑） -->
<uses-permission android:name="android.permission.RECEIVE_BOOT_COMPLETED" />

<application>
    <!-- 大肥鱼桌宠悬浮窗 -->
    <service
        android:name="com.somnacare.gemmallm.PetOverlayService"
        android:exported="false"
        android:foregroundServiceType="specialUse">
        <property
            android:name="android.app.PROPERTY_SPECIAL_USE_FGS_SUBTYPE"
            android:value="sleep_bedtime_companion_overlay" />
    </service>

    <!-- 护眼滤镜（如果还没声明） -->
    <service
        android:name="com.somnacare.gemmallm.EyeCareService"
        android:exported="false" />

    <!-- 快捷设置磁贴（可选） -->
    <service
        android:name="com.somnacare.gemmallm.EyeCareTileService"
        android:exported="true"
        android:permission="android.permission.BIND_QUICK_SETTINGS_TILE">
        <intent-filter>
            <action android:name="android.service.quicksettings.action.QS_TILE" />
        </intent-filter>
    </service>
</application>
```

> `specialUse` 的类型字符串（`sleep_bedtime_companion_overlay`）必须是**声明之外另加 `<property>`**，
> 否则 Google Play 上架会被驳回。本应用是自用/免费分发，但仍按规范写。

## 二、`assets` 的投放路径

`WhaleGirlView` 用 `getAssets().open("pet/" + name + ".png")`，
`PetOverlayService.loadSticker` 用 `getAssets().open("pet/stickers/" + name + ".webp")`。

所以下面两个目录的内容必须原样进到 APK 的 assets 里：

```
plugins/cap-gemma-llm/android/src/main/assets/pet/*.png            (22 张, 2.9 MB)
plugins/cap-gemma-llm/android/src/main/assets/pet/stickers/*.webp  (8 张, 154 KB)
```

Capacitor 插件的 `android/src/main/assets/` 会自动并入宿主 assets，
不需要额外拷贝——但**需确认 `build.gradle` 的 `sourceSets` 没有被改写**。

## 三、必须在真机上验的 4 件事

静态核对证明不了下面这些，只能装上去看：

1. **悬浮窗能出现**——`SettingsTab` 打开「大肥鱼桌宠」→ 授予「显示在其他应用上层」→ 回到桌面。
   若没出现，先看 `adb logcat | grep -i pet`，最可能是清单里 service 没声明。
2. **深夜/午后/清晨三张图会换**——`describeWake` 式的时段由 Web 侧算好推来，
   原生每 5 分钟重读一次。可以在设置页看到当前时段，和悬浮窗上的表情对照。
3. **贴图会出现在气泡里**——点她弹出播报，气泡顶部应有一张方图。
   若没有，多半是 `assets/pet/stickers/` 没进包（`loadSticker` 取不到会**静默跳过**，
   这是刻意设计：缺一张图不该让整条播报失败）。
4. **报错时会抖**——`error` 声明的 `once` + `shake` 本次才实现（原实现只认
   `blink`/`pingpong` 与 `float`/`wiggle`，所以声明为 `once` 的图会无限循环、
   声明为 `shake` 的图不抖）。触发方式：在未授权时打开桌宠，或在护眼开关失败时。

## 四、本地能验 / 不能验的边界

| 项目 | 本地（本仓库） | 构建环境 |
| --- | --- | --- |
| TS 类型与构建 | ✅ `npm run check` | — |
| 五个区域捎报词覆盖 | ✅ 144 项断言 | — |
| 精灵图帧数 == 图片宽度 | ✅ 读 PNG 头反推 | — |
| Web/原生贴图字节一致 | ✅ 逐字节比对 | — |
| 时段/情绪枚举顺序 TS ↔ Java | ✅ 比对两边书写顺序 | — |
| **Java 能否编译** | ❌ 无 `android/` 工程 | 必须 |
| **悬浮窗能否显示** | ❌ | 必须 |
| **`once`/`shake` 动效观感** | ❌ | 必须 |
